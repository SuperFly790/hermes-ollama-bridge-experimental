# Known limitations and non-goals

1. **Lossy compression:** `condense()` does not preserve all middle-history details. `build_summary()` takes up to 220 characters per message and reserves a small bounded section for uppercase hyphenated identifiers. A canary identifier can survive while its semantic relation is lost; IDs may be dropped when too numerous. This is not durable task state or a receipt log.
2. **Model quality:** A local 9B model was unable to reproduce a protected tail marker during a previous test; that test had adjacent `user` messages, conflicting terminology, large synthetic repeated text and a strongly cautionary system message. Root cause remains unresolved. The rewritten neutral handoff and identifier extractor have **not** been live-tested.
3. **Context budgeting:** Token counts are heuristic; `prompt_eval_count` is the actual count reported by an Ollama response, not a proof that the upstream accepted every intended message. No fixed ratio universally guarantees against context truncation across models, languages and tool schemas.
4. **Unsafe tool affordances:** The tool filter is based on declared names. When explicitly enabled, even `read_file` and `search_files` may read credentials; their results can later be forwarded to a cloud model by the caller. Keep tools disabled and agent sessions isolated.
5. **Side-effect replay:** The bridge cannot prove whether an earlier browser click, terminal command or file write executed when its tool result is missing. There is no durable in-flight action journal. Do not use for autonomous recovery.
6. **Streaming contract:** On upstream truncation the bridge emits `data: {"error":...}` and closes without `[DONE]`. Some OpenAI-compatible clients may fail to propagate the error. Compatibility with Hermes's real streaming client is untested.
7. **SSE partial content:** The bridge can emit text tokens before learning the upstream stream will truncate. Consumers must discard/mark partial answers rather than accept them as final.
8. **Local interface:** Loopback-only binding is not authentication. Any local process with the address could send requests. A machine with untrusted local users is not an appropriate security boundary.
9. **Windows runtime:** The single-instance lock and DPAPI implementation use Win32. The unit tests exercise pure Python logic on other operating systems but serving is designed for Windows.
10. **Performance:** An observed 15,851-token input took 91.55 s on an AMD UMA system. Do not extrapolate linearly or assume operation under an agent's timeout.
11. **Test evidence:** Historical `gate_v4_results.json` and `ollama_real_gate_v4.py` were not revision-synchronized and are deliberately excluded. Historical raw dumps, local paths and logs are never part of this repository.
12. **Logging and spill:** Metadata logs may contain system metadata and paths. Full prompts can be stored if the operator explicitly enables spill; keep them outside the repository and apply local access controls.
13. **Resource exhaustion:** Input size is capped, but the bridge is not hardened against malicious local callers, very large input arrays, deeply nested JSON or arbitrary environment variable combinations. No adversarial fuzzing or load test has been performed.
14. **No production recommendation:** No E2E verification of live Hermes failover, provider compatibility, thread-safety under real load, or safe recovery from upstream failures. A successful offline test is not a security certification.
